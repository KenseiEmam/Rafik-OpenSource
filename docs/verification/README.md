The message directory now has one scroll owner and its search remains fixed. The People list excludes people with an existing direct conversation; the API also enforces one direct pair per institution. People and conversations share search, including searching direct conversations by participant name, and use one empty state. Contact opening and message sends suppress redundant success notices. Other configured command toasts describe the outcome, and inline success copy clears after five seconds. SweetAlert toasts no longer pause indefinitely on hover. Frontend/backend typechecks, formatting and docs links passed after these changes. Focused browser and backend test attempts were blocked before test execution by Windows `spawn EPERM` errors while launching Docker/worker processes; assertions for scroll ownership, removed contacts and absent contact-save feedback remain unverified.

Frontend and backend typechecks passed. The shared password rule and HTML pattern cases passed directly in Node, and `npm run docs:check` checked 43 monorepo documents. The focused messaging browser journey ran in Chromium desktop and WebKit phone. Both engines completed contact selection, duplicate-pair reuse, sending/reloading messages, and layout/accessibility checks; the run stopped at a stale assertion for the no-match search copy, which has since been updated. The first migration attempt used an old cached image (45 migrations); rebuilding from the current checkout found 49 and applied the two pending migrations, `202610171200_published_programs_catalog` and `202610171300_unique_private_conversations`. The local API database password was preserved.
